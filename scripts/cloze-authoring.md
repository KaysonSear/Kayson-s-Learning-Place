# 挖空题与三题练习撰写规范

本文件供分批撰写题库的代理使用。只写分配给你的文件，不要改动其他文件。

## 源文

- 新原文：`content/Coding · C.md`（已替换为最新 Obsidian 笔记）。
- 每个知识点的正文从 `#### N. 标题` 下一行开始，到下一个 `###` / `##` / `####` 前结束。
- 题目必须**逐字复制**该正文中的连续片段，不能改写、补充、翻译或换行重排。

## 1. 挖空题

写入 `content/cloze/chNN[-后缀].json`，`NN` 是两位章号（如 `ch04.json`、`ch07-a.json`）。

```json
{
  "format": "cloze-bank-v1",
  "chapter": 4,
  "questions": [
    {
      "pointId": 128,
      "quote": "`!cond` 表示原条件不成立。……`!(a && b)` 等价于 {{!a || !b}}，`!(a || b)` 等价于 {{!a && !b}}。",
      "options": [
        ["!a || !b", "!a && !b"],
        ["!a && !b", "!a || !b"],
        ["a && b", "a || b"],
        ["!a", "!b"]
      ],
      "note": "德摩根律……错误项只改了一边……"
    }
  ]
}
```

规则：

- 每个知识点恰好一题，`pointId` 等于标题编号。
- `quote` 用 `{{原文}}` 标出 1–3 个空。去掉标记后的文本必须是该知识点正文的连续片段（空白归一化后匹配）。
- 空位可以放在行内代码中（如 `` `{{main}}` ``），但不能跨行内代码或 `$…$` 公式的边界；两个空之间必须有可见文字。
- 原文中不要出现 `{{`、`}}`、`____`；若 C 代码本身有双花括号，换一段或缩小范围。
- `options` 恰好 4 项，`options[0]` 是正确组合。每项是数组，长度等于空数；多空题的每个分量不能含分号。显示时会用 `; ` 连接，如 `main; 0`。
- 选项是纯文本（不要写反引号、`**` 等 Markdown 标记）；正确项必须与 `{{}}` 中的原文完全一致（去掉 Markdown 标记后）。
- `note` 写 1–2 句点评：正确项为何成立，主要干扰项错在哪。不要复述题干。
- 可选 `excerpt`：默认自动取包含该空的完整原段（表格题取整张表，代码题取整个围栏）。如果自动匹配有歧义，再手写 `excerpt`。
- 默认只挖 1 个空；成对事实、表格行、两个参数/类型等才挖 2–3 个。

## 2. 三题练习

第 1–10 章写 `content/practice/a/chNN[-后缀].txt`，每行：

```
id§promptA§answerA§promptB§answerB
```

第 11–19 章写两份：

- `content/practice/b-a/chNN[-后缀].txt`：`id§promptA§answerA`
- `content/practice/b-b/chNN[-后缀].txt`：`id¦promptB¦answerB`

规则：

- 每个知识点 A、B 各一题；A 考查该点的直接事实/规则，B 换一个具体情境或代码片段考查迁移。
- 题干长度 > 12 字，答案尽量短；不要包含 `§`、`¦` 或换行。
- 是/否题答案写 `Y` 或 `N`。
- 多个可接受答案：第 1–10 章用 `~` 分隔（如 `argv[1]~1`），第 11–19 章用 `;;` 分隔（如 `-3;;−3`）。
- 不要用「上题」「下一题」「如图所示」「【填空】」等表述。
- 解析和提示由构建脚本自动生成，不用写。

## 3. 校验

只校验你负责的范围：

```sh
node scripts/validate-cloze.ts 起始点-结束点
node scripts/validate-practice.ts 起始点-结束点
```

两条都必须 `PASS`。如果报错，按提示修改后重跑；不要改动其他批次的文件。
